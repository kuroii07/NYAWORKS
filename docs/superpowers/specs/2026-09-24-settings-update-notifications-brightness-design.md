# NYAWORKS 设置、更新提示与界面亮度设计

日期：2026-09-24  
状态：用户已确认

## 1. 目标

在不改变既有主题、语言、首页布局和导航逻辑的前提下，补齐常规设置中的四项能力：

1. 重置所有设置。
2. 启动时自动检查更新。
3. 新功能提示与右上角通知入口。
4. 跟随当前主题工作的界面亮度调节。

所有新增控件沿用 NYAWORKS 已确认的暗色主题、图标、圆角、描边、动效和五语言规范。

## 2. 设置页布局

### 常规

排列顺序：

1. 启动页面
2. 记住上次页面
3. 自动检查更新
4. 界面与图标大小
5. 重置所有设置

“自动检查更新”使用现有开关组件，默认开启。

“重置所有设置”左侧为重置图标和文字，右侧为紧凑描边按钮。点击后打开 NYAWORKS 自定义确认窗口，不使用浏览器或 Windows 原生确认框。

### 交互与提示

排列顺序：

1. 鼠标提示
2. 提示延迟
3. 界面动效
4. 显示新功能提示
5. 危险操作确认

“显示新功能提示”默认开启。

### 外观与主题

“界面亮度”放在“当前语言”和“首页 Banner”之间，即首页 Banner 上方。控件由图标、文字、主题色滑杆和百分比组成。

## 3. 设置数据

`GeneralSettings` 新增：

- `autoCheckUpdates: boolean`，默认 `true`
- `showWhatsNew: boolean`，默认 `true`
- `interfaceBrightness: number`，默认 `100`

亮度有效范围固定为 `90–110`，步长为 `1`。读取损坏或越界数据时回退到 `100`。

现有设置存储键保持不变，通过字段归一化兼容旧版本数据。

## 4. 界面亮度

- 亮度以当前主题为基础做相对调整，不创建亮色模式。
- `90%` 只轻微压暗，`110%` 只轻微提亮，保证文字、描边和主题色仍清晰。
- 调整即时生效并本地保存。
- 主界面、顶部菜单、自定义下拉和自定义弹窗保持一致亮度。
- 不改变主题色选择本身；切换主题后继续沿用当前亮度百分比。

## 5. 自动更新检查

### 数据源

第一阶段读取 GitHub 仓库 `kuroii07/NYAWORKS` 的最新 Release：

`https://api.github.com/repos/kuroii07/NYAWORKS/releases/latest`

仅使用公开接口，不需要 Token。

### 启动流程

1. 扩展完成基础界面加载。
2. 若“自动检查更新”关闭，则不发起请求。
3. 若开启，则每次扩展启动请求一次最新 Release。
4. 对当前 `PRODUCT_VERSION` 和远端 tag 做标准化版本比较。
5. 远端版本更高时，打开自定义更新窗口。
6. 当前版本相同或更高时，不显示窗口。

### 更新窗口

显示：

- 新版本号
- Release 标题
- 更新摘要
- “前往更新”
- “暂不更新”

“前往更新”使用现有安全外链能力打开对应 GitHub Release 页面。第一阶段不自动下载、不覆盖扩展文件、不自动重启 AE。

“暂不更新”只关闭本次窗口，不记录忽略状态。只要设置仍开启且用户尚未安装新版本，下次启动继续提醒。安装新版本后，当前版本与远端版本一致，提醒自然停止。

### 异常处理

- 网络断开、超时、GitHub 限流、仓库尚无 Release 或返回数据无效时静默跳过。
- 更新检查失败不得阻塞扩展启动，不弹出错误骚扰用户。
- 开发环境可在控制台保留简短诊断信息。

## 6. 新功能提示

### 顶部入口

- 在主题按钮左侧增加常驻“新功能”按钮。
- 图标使用铃铛类图标，避免与 AI 页的闪光图标重复。
- 当前安装版本存在未读更新说明，且“显示新功能提示”开启时，按钮显示主题色提示点。
- 设置关闭时按钮仍保留，可手动查看，但不显示主动提示点。

### 内容与已读状态

- 当前版本更新内容保存在本地版本说明数据中，随扩展包发布。
- 使用独立本地键记录用户最后查看的产品版本。
- 新版本首次运行时，当前版本高于已读版本，显示未读提示点。
- 用户打开新功能窗口后，将当前版本记为已读，提示点消失。
- 后续再次点击按钮仍可查看当前版本内容。

### 新功能窗口

显示：

- 当前版本号与发布日期
- 新功能
- 优化
- 修复

窗口使用与更新确认窗口一致的 NYAWORKS 自定义弹窗，不使用系统原生弹窗。

## 7. 重置所有设置

点击后显示自定义确认窗口，并说明会恢复：

- 默认主题：极夜青
- 默认语言：简体中文
- 默认界面密度：中
- 默认启动页：首页
- 自动检查更新：开启
- 显示新功能提示：开启
- 界面亮度：100%
- 其他常规交互开关的默认值
- 上次停留页面记录

重置完成后立即应用，并返回首页。

当前阶段不删除用户资源文件。未来 AI 功能接入后，API Key 不由“重置所有设置”静默删除，密钥删除必须提供单独且明确的操作。

## 8. 组件边界

- `UpdateService`：请求 GitHub Release、解析响应、比较版本。
- `UpdateProvider`：管理启动检查、更新窗口状态和版本结果。
- `WhatsNewButton`：顶部入口、未读提示点。
- `AppDialog`：更新提示、版本说明和重置确认共用的自定义弹窗外壳。
- `BrightnessControl`：亮度滑杆与百分比。
- `SettingsProvider`：保存新增常规设置并提供重置入口。
- `releaseNotes`：当前安装版本的本地更新内容。

更新网络逻辑不得直接写入设置页面或顶部组件。

## 9. 可访问性与交互

- 按钮、滑杆和弹窗均提供五语言可访问名称。
- 弹窗支持 Esc 关闭、点击遮罩关闭、键盘焦点管理。
- 更新确认窗口中的主要操作为“前往更新”，次要操作为“暂不更新”。
- 重置确认窗口明确展示影响范围，确认按钮使用危险操作视觉，但不使用刺眼的大面积红色。
- `prefers-reduced-motion` 和现有“界面动效”设置继续生效。

## 10. 测试与验收

自动化测试：

- 新设置字段默认值、持久化、损坏数据和亮度边界归一化。
- 版本号比较，包括预发布版本和带 `v` 的 tag。
- GitHub Release 响应解析与异常回退。
- 自动检查开关的分支行为。
- 新功能已读状态。
- 重置操作恢复所有当前 UI 偏好，但不删除用户资源与 API Key。
- 五语言新增文案完整。

浏览器验收：

- `520 × 960` 默认窗口及最小窗口无横向溢出。
- 四项设置位置与需求一致。
- 亮度 `90% / 100% / 110%` 在五套主题下均可读。
- 右上角新功能按钮、提示点和两类弹窗视觉统一。
- 网络失败不会影响界面进入和已有功能。

AE 宿主验收：

- CEP 启动时更新检查不阻塞面板。
- 外部更新链接能够通过 CEP 安全打开系统浏览器。
- 关闭和重新打开面板后，设置及提醒逻辑符合预期。

## 11. 非本阶段范围

- 自动下载安装更新包。
- 自动覆盖 CEP 扩展目录。
- 自动关闭或重启 After Effects。
- 更新签名、安装器提权及 Windows/macOS 安装差异。

这些能力保留到主要功能开发接近完成后再单独设计。
