# NYAWORKS 图层本地化与兼容性设计规范

**日期：** 2026-10-11
**状态：** 作为后续相关功能的开发规范
**适用范围：** 新建图层九宫格、图层控制器、伪效果参数和其他会在 AE 工程中创建用户可见对象的功能

## 1. 背景与目标

上一轮完成了新建图层九宫格的共享 Host 执行链，并补齐了调整层的第一轮稳定实现：全合成尺寸、沿用选区时间范围、插入选区上方、创建后只选中新层、重名递增且不自动添加效果。当前实现仍有一个长期问题：图层名称、伪效果名称、参数名称和部分表达式引用主要使用简体中文硬编码。

本规范解决两个问题：

1. 新建对象应跟随当前 NYAWORKS 面板语言，让 English、繁體中文、日本語和 한국어 用户不会被强制看到中文对象名称。
2. 本地化不能破坏已验证的中文功能、已有工程、伪效果索引、表达式和 AE 2025 运行稳定性。

本规范只规定边界和契约，不要求一次性改造全部图层或全部伪效果。每个功能必须在自身需要用户可见名称或伪效果控件时接入；纯内部 Action、日志和稳定 ID 不强制本地化。

## 2. 已确认的基线

### 2.1 调整层基线

调整层属于普通图层，不依赖伪效果。当前实现和自动化回归必须保持：

- 图层类型为真正的 Adjustment Layer；
- 尺寸等于当前合成宽高和像素宽高比；
- 无选区时使用完整合成时间范围；有选区时使用选区并集的 `inPoint/outPoint`；
- 插入到选区上方；无选区时使用默认堆叠位置；
- 创建后只选中新层；
- 默认名称为当前语言的调整层名称，同名时使用递增后缀；
- 不自动添加 Fill、伪效果或其他效果；
- 整个操作继续使用一个 Undo Group，并在 Host 侧完成最终状态校验。

2026-10-11 的调整层自动化回归已覆盖上述行为，但 Windows / 中文 AE 2025 的实机验收仍单独记录，不把自动化结果写成宿主验收。

### 2.2 当前中文伪效果基线

以下中文资产和内部身份视为已验收兼容基线，不因本规范重命名、重排参数或覆盖文件：

- 圆角矩形：`rounded-rectangle-zh-CN.ffx`，内部身份 `Pseudo/NYA_RRect_v7_zhCN`；
- Alt 圆形：`circle-zh-CN.ffx`，内部身份 `Pseudo/NYA_Circle_v3_zhCN`；
- Ctrl 三角形：`triangle-zh-CN.ffx`，内部身份 `Pseudo/NYA_Triangle_v1_zhCN`；
- Shift 星形：`star-zh-CN.ffx`，内部身份 `Pseudo/NYA_Star_v2_zhCN`。

这些资产的参数顺序、参数索引、属性类型、默认值、拖动范围、键盘输入上限、marker 和表达式契约均属于冻结内容。`PresetEffects.xml` 不是运行时依赖，也不是用户安装步骤。

## 3. 语言与名称模型

### 3.1 支持语言

第一批语言沿用现有 Language 系统：

- `zh-CN`
- `zh-TW`
- `en`
- `ja`
- `ko`

新建对象使用当前 NYAWORKS 面板语言，不读取或猜测 AE 界面语言。面板语言缺失或无效时回退到 `zh-CN`，并保持旧调用方兼容。

### 3.2 稳定 ID 与显示名称分离

每个功能至少有三类值：

- `actionId`：Action Registry 使用，例如 `create-adjustment`；
- `objectId/effectId`：Host、测试和 Catalog 使用的稳定内部身份；
- `displayName`：写入 AE 图层名、效果实例名或参数标签的本地化文本。

稳定 ID、schema 版本、参数语义 ID、marker 和模板契约不能依赖显示语言。显示名称可以变化，稳定 ID 不能因为翻译或文案调整而变化。

当前历史 `zh-CN` 伪效果的 `matchName` 含有 `zhCN` 后缀，必须保持原样；它们属于旧工程兼容契约。后续新增语言模板不得通过覆盖旧文件实现，需由 Catalog 明确映射。若 AE 制作流程要求新语言使用独立 `matchName`，只能新建版本/语言条目，不能修改或复用已发布中文条目的参数顺序。

### 3.3 名称目录

新增用户可见名称统一进入本地化 Catalog 或现有 `src/i18n/` 资源，不在 Host 函数中散落多份硬编码。Catalog 至少覆盖：

- 普通图层：文字、纯色、形状、调整层、空对象、摄像机、灯光、预合成；
- 形状伪效果：效果实例名、参数标签、分组标题；
- 错误和兼容警告：模板缺失、语言未就绪、回退到兼容模式。

同一个语言条目的名称必须在 UI、Host 结果、测试夹具和 AE 实机记录中保持一致。名称长度不可假设固定，面板 UI 需要按五语言检查溢出；AE 图层名允许自然增长，但不得丢失对象类型识别。

## 4. 旧工程与旧调用方兼容

### 4.1 已有图层不自动改名

切换面板语言、打开旧工程、刷新扩展或重新读取图层时，不能批量重命名已有图层、效果实例或表达式。用户主动执行“重命名”类功能时才允许改变显示名称，并必须单独定义其范围。

### 4.2 `zh-CN` 路径保持原行为

以下内容在本地化改造后必须与当前版本等价：

- 未携带语言字段的旧 Bridge payload；
- `zh-CN` 新建图层的名称、默认值、层级、时间范围和插入位置；
- 现有中文伪效果的文件、`matchName`、marker、参数索引和表达式；
- 已保存工程中通过效果实例名访问的中文表达式。

语言字段属于向后兼容的可选字段。旧调用方不传语言时，Host 使用 `zh-CN`，不能因为新增语言路由而拒绝旧 payload。

### 4.3 失败必须发生在创建前

当目标语言需要伪效果模板、但模板或 Catalog 尚未就绪时，必须在创建图层前完成能力检查。不可先创建半成品，再因为本地化资源缺失留下错误图层。

过渡阶段的策略是：

- 普通图层可直接使用已完成的语言名称；
- 伪效果功能只有在该语言的模板、Catalog、表达式映射和 AE 2025 验收均完成后才标记为“本地化可用”；
- 未完成语言不静默伪装成完整本地化。若产品仍需保证功能可用，必须使用既有安全回退路径，并在结构化结果中明确标记 `warning`；不修改已有中文模板。

## 5. 伪效果多语言模板规范

### 5.1 目录与 Catalog

新增语言资产采用独立目录，不覆盖当前中文平铺文件。推荐源文件结构：

```text
assets/pseudo-effects/<shape>/v<version>/<locale>/schema.json
assets/pseudo-effects/<shape>/v<version>/<locale>/source.*
public/host/pseudo-effects/<locale>/<artifact>.ffx
```

现有 `public/host/pseudo-effects/<artifact>-zh-CN.ffx` 和 `catalog.json` 条目继续保留。Catalog 可同时识别旧平铺条目与新语言目录，迁移过程不得要求已保存工程重新应用效果。

每个语言条目至少包含：

- `effectId`、`shape`、`schemaVersion`、`locale`；
- `.ffx` 相对路径；
- `matchName`、marker、显示名称；
- 参数语义 ID、顺序、索引、属性类型和默认值；
- 几何参数与样式参数的拖动范围、输入上限和表达式契约；
- 支持的 AE 版本范围和验证状态。

### 5.2 参数契约不可因翻译改变

翻译只改变用户看到的文字，不改变：

- 参数数量和顺序；
- 参数索引和 AE 属性类型；
- 默认值、数值语义和边界；
- 表达式计算逻辑；
- Undo、复制、保存重开和关键帧行为。

新增参数只能追加。破坏性变更必须发布新的 schema / 内部身份，并让旧版本继续可读；不能通过改名或重排让旧工程“自动适配”。

### 5.3 表达式引用策略

Host 生成表达式时必须使用本次实际创建出的本地化效果实例名，不能假设固定中文名称。短期内如仍需 `effect("...")(index)` 形式，名称由 Host 在创建后获取并安全编码；参数索引来自 Catalog 契约而非翻译文本。

长期改造目标是减少对显示名称的依赖：优先通过稳定的对象契约、固定索引和 Host 返回的映射生成表达式。任何名称解析失败都应在同一个 Undo Group 内清理本次新建内容并返回结构化错误。

## 6. 安全、验证与发布门槛

### 6.1 TDD 顺序

每个本地化功能按以下顺序推进：

1. 先为稳定 ID、语言 Catalog、旧 payload、中文回归和失败前置检查写失败测试；
2. 运行窄测试确认 RED；
3. 实现最小改动；
4. 运行相关测试、类型检查、构建和 dist smoke；
5. 在 Windows / 中文 AE 2025 实机确认后，才更新功能状态；
6. 发现回归时优先回退语言路由或关闭未完成语言能力，不改动已验收中文资产。

### 6.2 必须区分的验证层级

- 自动化 Host / Bridge：验证调用契约、参数、清理和失败边界；
- TypeScript / 构建 / dist smoke：验证工程和产物完整；
- CEP 面板：验证语言切换、名称展示和交互；
- Real AE：验证真实图层、效果控件、表达式、关键帧、Undo、复制、保存重开和刷新后继续工作。

浏览器或 Mock 通过不得写成 AE 实机通过。验收记录必须包含 AE 版本、系统、AE 界面语言、NYAWORKS 面板语言、扩展加载方式和未测范围。

### 6.3 回滚门槛

出现以下任一情况时，本轮不得继续扩大语言覆盖：

- `zh-CN` 新建图层名称或行为变化；
- 已有中文伪效果表达式断裂；
- 新建失败后留下半成品图层或额外效果；
- 关闭/刷新扩展后 AE 工程状态异常；
- 真实 AE 与自动化测试的参数顺序或默认值不一致。

回滚应优先关闭未完成语言的能力开关，保留稳定 ID 和文档，不删除旧资产、不改写 Git 历史、不修改 AE 安装目录。

## 7. 非目标

- 不在本规范中重新设计首页九宫格或 Action Registry；
- 不自动翻译 AE 原生 UI 或系统语言；
- 不迁移已有中文工程中的图层、效果或表达式；
- 不修改 `PresetEffects.xml` 作为产品安装或运行方案；
- 不为了本地化一次性重构所有 Host 业务逻辑；
- 不把尚未通过 AE 实机的语言标记为正式支持。

## 8. 后续接入判断

只有当功能满足以下任一条件时，才必须使用本规范：

- 会在 AE 工程中创建用户可见图层、控制器、效果或参数；
- 会生成引用效果实例名或参数索引的表达式；
- 会读取、复制、保存或重新打开带有 NYAWORKS 自定义对象的工程。

只在面板内部使用的搜索关键词、Action ID、日志字段和测试内部 fixture 可以保持稳定英文/机器值，不需要生成五语言显示名称。
