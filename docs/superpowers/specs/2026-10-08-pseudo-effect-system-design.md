# NYAWORKS 共享伪效果系统设计

日期：2026-10-08

状态：规划文档；未实现、未制作模板、未进行 AE 宿主验收。

代码核对基线：`d49d6ff`，`feature/settings-updates`。

## 1. 结论与本轮边界

把伪效果定义为 NYAWORKS 的共享参数基础能力，而不是圆角矩形的专用界面：

> 参数规格 + 内置 `.ffx` 控件模板 + 模板目录 + Host 加载器 + 参数绑定 + 版本兼容规则。

各工具继续负责自己的形状生成、摄像机计算、文字动画或效果处理；共享系统只负责把参数可靠地放进 AE 效果控件，并提供可验证的访问方式。

本轮只沉淀规划和文档，不修改现有 Host、Action、界面或构建代码，不制作 `.ffx`，不安装制作工具，不改 AE 安装目录，不迁移旧工程，不生成测试包。以下接口、目录及名称均是设计提案，不表示已经存在；具体实施计划在后续明确启动开发后再拆分。

| 事项 | 规划结论 |
| --- | --- |
| 推荐交付方式 | 随 NYAWORKS 携带经过验证的伪效果 `.ffx`，执行工具时按需加载 |
| 对用户的要求 | 不要求安装伪效果制作器或修改 `PresetEffects.xml`；这也是发布验收条件 |
| 入口 | 复用现有 Action 执行链，不另做一套工具注册或执行系统 |
| 第一阶段作用对象 | 工具本次新建的图层/控制器；不自动升级已有对象 |
| 第一批接入候选 | 参数化形状和摄像机控制器，至少两类不同结构证明复用 |
| 旧工程 | 保持原生控件和原有表达式，不扫描替换、不自动迁移 |
| 五语言 | 与现有语言系统共用文案来源；实例语言在创建时确定，旧实例不随面板语言重建 |
| 验证状态 | 可行性有公开实现参考；NYAWORKS 自身兼容性全部待实测 |

## 2. 要解决的问题与适用范围

### 2.1 用户体验目标

用户仍从首页、全局搜索或后续功能页执行同一个工具。工具创建完成后，在 AE 的“效果控件”中调整一组有清晰名称、分组、单位和默认值的参数，不需要理解 `.ffx`、模板路径或伪效果注册。

一个功能实例优先对应一组必要的控件；复杂功能可以包含多个控制器，但不能把所有工具的参数堆进同一个万能效果。普通参数和高级参数分组，避免长说明充当参数名称。关闭 NYAWORKS 后仍能调整参数和渲染是设计目标，必须通过离线及跨电脑验收。

### 2.2 功能适用矩阵

| 功能类别 | 适用方式 | 接入边界 |
| --- | --- | --- |
| 圆角矩形、圆、多边形、星形 | 尺寸、圆角、半径、角数等持续可调参数 | 首批候选；保留现有几何算法和默认值 |
| 摄像机控制器 | 目标、位移、旋转、镜头、焦点、抖动分组 | 首批候选；控制器承载参数，摄像机仍保留原生属性 |
| 文字与排版控制器 | 间距、顺序、延迟、幅度等动画参数 | 后续候选；不把文字编辑器或整段文本强行搬入伪效果 |
| 动画工具 | 弹性、循环、跟随等需要长期保留的控制参数 | 后续候选；算法仍归所属工具 |
| 效果组合、动态图形 | 统一驱动若干原生属性或真实效果 | 后续候选；不隐藏、替代真实渲染效果 |
| 布局、阵列、分布 | 用户需要反复调整的数量、间隔和偏移 | 后续候选；一次性操作无需强加控制器 |
| 锚点、对齐、选择、资源扫描 | 通常是执行一次的操作 | 不为统一外观添加无必要的伪效果 |
| 纯色层 Fill | 已有直接可用的颜色入口 | 保留原生 Fill，不重复创建“颜色控制” |

候选不等于承诺开发全部功能；各业务工具仍需独立规格、授权范围与验收。

### 2.3 能力边界

伪效果提供参数组织，本身不是渲染插件；需要表达式或脚本把参数连接到实际属性。它也不会让被驱动的真实效果从效果列表中消失。依据：[BatchFrame 制作器说明](https://batchframe.com/support/manuals/pseudo-effect-maker/)。

本系统不承担 `.aex` 原生效果开发、任意 HTML/CSS 界面、点击按钮执行脚本回调，也不承诺动态隐藏/禁用参数或任意可编辑文本。控制类型、关键帧、表达式和菜单行为逐项验证，不能把制作工具中的显示能力直接当成 AE 运行时能力。

## 3. 当前工程基线

当前实现位于 [`public/host/index.jsx`](../../../public/host/index.jsx)，尚无共享伪效果加载器或正式模板资产。

| 当前入口/函数 | 已有行为 | 未来接入时保留什么 |
| --- | --- | --- |
| `addLayerControl()` | 添加原生 Expression Controls 并赋中文显示名 | 作为兼容路径保留；不全局替换所有调用 |
| `createRoundedRectangleShape()` | 宽、高、总圆角、分离圆角开关及四角半径，共八个独立控件 | 初始值 `500 / 500 / 50`、四角限制及路径生成规则 |
| `createEllipseShape()` / `createPolygonShape()` | 半径、角数、角度、内外圆角等独立参数 | 各形状不同的参数语义，不强行共用同一参数布局 |
| `addCameraControllerControls()` | 目标、位置、旋转、移动、镜头、焦点及抖动参数 | 控制器/摄像机层级、时间范围、坐标计算和初始化逻辑 |
| 纯色层创建 | 直接添加原生 `ADBE Fill` | 保持一个清晰的颜色入口 |
| 用户资源预设执行 | 对用户选层应用外部 `.ffx` | 保持用户资源语义；内部模板不能直接复用其批量选层逻辑 |

目前表达式存在按显示名称读取控件的写法，例如 `effect("Nya 宽度")(1)`。新系统要解决新的绑定稳定性，不能借机改写已有工程中的这些表达式。

新建图层原规格见 [`2026-10-04-layer-creation-grid-design.md`](2026-10-04-layer-creation-grid-design.md)。本规格补充共享参数层，不改变原有修饰键、选层、命名、插入位置或预合成行为。

## 4. 技术路线与架构

### 4.1 三条路线

| 路线 | 用途 | 选择 |
| --- | --- | --- |
| AE 原生 Expression Controls | 无模板依赖，延续当前实现 | 保留为现有方案及经过验证的降级路径 |
| 随扩展分发伪效果 `.ffx` | 保存控件定义，执行时加载并绑定 | 推荐路线，先验证干净环境可用性 |
| 修改 AE 安装目录中的 `PresetEffects.xml` | 制作/研究时可能遇到的定义方式 | 不作为用户安装或运行时流程 |

制作器文档介绍了 `.ffx` 分发方式；RxLab 也提供了伪效果加载及参数映射的公开实现。这些是路线依据，不是 NYAWORKS 的宿主验证结果。参见 [BatchFrame](https://batchframe.com/support/manuals/pseudo-effect-maker/)、[DuAELayer](https://rxlab.guide/dusan/reference/DuAELayer.html)、[DuAEPseudoEffect](https://rxlab.guide/dusan/reference/DuAEPseudoEffect.html)。

### 4.2 复用现有执行链

```text
首页 / 全局搜索 / 功能页
          ↓
现有 Action Service / Registry / Context / Runner
          ↓
现有固定命令 Executor → Bridge → Host 业务 Action
                                  ├─ 参数化形状
                                  ├─ 摄像机控制器
                                  └─ 后续工具
                                        ↓
                              共享伪效果 Host Helper
                              ├─ 模板解析与校验
                              ├─ 隔离加载与实例识别
                              └─ 参数访问与绑定校验
```

- 模板目录只描述数据资产，不是第二个 Action Registry。
- UI 传递既有 Action 参数和经校验的语言，不传任意文件路径、表达式源码或 Host 命令。
- Bridge 只处理协议和结果，不承载形状/摄像机业务。
- Host 重新校验当前合成、目标图层和允许的模板，不能仅信任前端 Context。
- 共享 Helper 放在 Host 层；是否拆成小模块在实施时按现有加载方式决定，不重构整个 Host。
- 表达式在 AE 内求值，不通过 CEP 逐帧回调，不依赖 NYAWORKS 面板一直打开。

### 4.3 职责划分

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 参数规格 Schema | 稳定参数 ID、类型、单位、分组、默认值、约束和能力要求 | 选层、坐标变换、几何算法 |
| 模板目录 Catalog | 版本、语言、允许路径、实际 matchName、属性映射、校验摘要 | 工具入口或用户资源扫描 |
| `.ffx` 模板 | 已审核的控件定义与静态默认值 | 偷带图层变换、素材路径、用户动画或业务表达式 |
| Host Loader | 校验、目标隔离、加载、重新获取属性及失败清理 | 决定相机怎么移动、形状怎么绘制 |
| Binding Adapter | 把语义参数 ID 转成该模板的访问方式并验证 | 猜测用户现有表达式并强行改写 |
| 业务 Action | 创建对象、初始化上下文参数、安装业务表达式、汇总结果 | 为每个功能复制模板加载逻辑 |

## 5. 参数、模板与绑定契约

### 5.1 三种身份必须分开

1. **功能身份**：例如 `shape.roundedRectangle`、`camera.rig`，与语言无关。
2. **模板身份**：区分结构版本和语言变体，映射到实际效果 `matchName`。
3. **实例身份**：某一图层/控制器上属于某次业务创建的控件，不能只用显示名称判断。

示意模板 matchName 可为 `Pseudo/NYA_RRect_v1_zhCN`；这不是已经注册的名称。命名需简短、唯一，并在最终制作工具和实际导出物中核验前缀及长度约束。

2026-10-09 产品命名规则：确认可用的交付 `.ffx` 以功能和必要的语言标识命名，例如 `rounded-rectangle-zh-CN.ffx`，文件名不追加 `v1`、`v2`。其他业务使用各自的功能名，不与圆角矩形复用同一份控件；Catalog 中的模板身份、效果内部 `matchName` 仍可区分不兼容的参数结构，不能仅为了改文件名而改写已有实例的内部身份。测试中发现有问题的成品从后续交付和 Catalog 中移除，不当作“历史版本”随包保留。

第一阶段每个业务实例只创建它所需的一份同类控件；重复调用加载助手不得重复添加或重置数值。用户再次执行“新建”应创建新图层，不属于重复调用。遇到同层多个无法区分的候选，返回歧义错误，不能默认取第一项。未来真正支持同层多实例时必须另有实例绑定契约。

### 5.2 参数规格

每个参数至少记录：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定语义键，如 `size.width`，不使用翻译名称 |
| `type` / `unit` | 控件类型和业务单位；角度、像素、百分比、秒等不能混用 |
| `groupId` / `labelKey` | 分组身份及现有 i18n 中的显示文案键 |
| `default` / 初始化策略 | 静态默认值或由业务上下文赋值；模板不能硬写本次合成中心 |
| 值域约束 | 区分拖动显示范围、允许输入范围和业务表达式约束 |
| 动画能力 | 是否允许关键帧、表达式；离散值的取整/保持规则单独声明 |
| 业务角色 | 用户可调参数或只读/隐藏的内部识别信息 |

圆角矩形的语义键可为 `size.width`、`size.height`、`rounding.radius`、`rounding.separate` 及四个角半径；摄像机可为 `target.layer`、`position.x`、`lens.focalLength` 等。它们共享规格规则，而不是共享同一张万能参数表。

控件是否可动画，与某个工具是否能安全修改已经带关键帧/表达式的目标属性，是两个问题；引入伪效果不自动解除锚点、对齐或其他业务 Action 的安全限制。

### 5.3 模板目录

每个已发布模板至少记录：

- `featureId`、`templateId`、`schemaVersion`、`bindingVersion`、`locale`。
- 实际 `matchName`、相对资产路径、SHA-256、制作源和导出记录。
- 最低目标 AE、实际通过的 AE/操作系统/语言组合、表达式引擎要求。
- `paramId → 实际属性索引或路径 → 类型/维度` 的核验映射。
- 识别标记的位置与预期值/名称、实例策略、允许的初始化参数。
- 兼容回退策略，以及模板不允许包含的额外属性。

属性编号必须从保存后的真实模板加载结果中取得，不能根据视觉顺序猜测为 `1…N`。分组等结构可能影响映射；模板描述和表达式访问要一同核对。参考 [RxLab 模板与 props 映射](https://rxlab.guide/dusan/reference/DuAEPseudoEffect.html)及其[公开实现](https://rxlab.guide/dusan/reference/DuAEF_DuSan_api.jsxinc.html)。

### 5.4 Host 识别与表达式读取

Host 可以核验效果 `matchName`，但不能假设表达式能直接使用 Host 的 `matchName` 属性。RxLab 的表达式库使用专门的属性标记识别效果类型，这说明两端需要不同的识别策略。参考 [DuAEExpression.Library](https://rxlab.guide/dusan/reference/DuAEExpression.Library.html)。

计划采用：

- Host 用 Catalog 中的 matchName、结构及内部标记共同识别，再取得该实例的参数句柄。
- 表达式使用经过验证的实例定位方式和固定参数映射；不把翻译后的效果名或参数名作为唯一依据。
- 原型优先验证“不可动画的内部类型标记 + 必要的实例标记”；实际存储方式、可读性和复制行为是可行性门槛，尚未定为已可用 API。
- 效果重命名、排序或追加其他效果后仍应正确读取。若需要查找，限定在明确控制层的效果范围内；禁止逐帧遍历整个工程。
- 跨层绑定优先研究明确的 Layer Control 或既有控制层关系，不依赖唯一中文层名；单独复制摄像机与成组复制的语义由摄像机规格定义。
- 每次添加效果后重新获取可能失效的属性引用，不跨结构修改长期保存旧引用。加载与引用风险可参考 [DuAELayer.applyPreset](https://rxlab.guide/dusan/reference/DuAELayer.html)。

签名验证失败、模板不匹配或实例歧义时不能静默绑定到另一个控制器。内部标记只是身份辅助，不是安全沙箱或授权机制。

## 6. 制作源、打包与内部资产边界

### 6.1 制作流程

1. 先确认语义参数规格和分组，再制作控件，不从某个截图反向硬编码业务。
2. 保留可编辑源文件及制作器版本；可使用 XML/JSON 工作流或合法取得的制作工具。工具选型、授权和分发条件在实施前确认，本规划不引入第三方运行库。
3. 保存正式 `.ffx` 后重新加载，核验实际 matchName、类型、索引、默认值及是否混入其他属性。不能把制作器中的临时预览当成正式模板。
4. 在最低目标版本及干净环境验证，再记录资产哈希、来源版本和实测矩阵。
5. 发布时模板、映射和绑定必须成套进入同一版本；二进制变化同时附可读参数差异，不能只提交一个无法审查的 `.ffx`。

制作器的临时 Apply 与正式 Save 在 matchName 行为上可能不同；AE 保存预设的向后兼容性也有限。因此保存后复验和最低版本导出/验证是必需步骤，而不是仅看文件扩展名。依据：[BatchFrame 制作流程说明](https://batchframe.com/support/manuals/pseudo-effect-maker/)。

“可复现”要求保留完整输入和导出步骤；未验证前不承诺不同 AE/工具导出的二进制逐字节相同。不能假设运行时可以仅凭一段 XML/JSON 在任意 AE 中创建完整伪效果。

### 6.2 建议资产布局

以下仅为目录职责提案，本轮不创建：

```text
assets/pseudo-effects/          可审查的参数规格、制作源、导出说明
public/host/pseudo-effects/     随扩展交付的 .ffx 与 Host 可用映射
tests/...                      规格、映射、加载边界和构建契约测试
docs/testing/...               模板和功能的真实 AE 验收记录
```

维护一份权威参数规格。制作源、Host 映射及语言变体若无法自动生成，也必须通过校验比对，禁止各功能手抄一份索引。

- 内部 `.ffx` 不属于资源设置页的用户预设；不添加内置来源、不扫描展示、不增加“双击使用”按钮。
- 用户自定义目录中的脚本/预设及已有执行方式完全不受影响。
- 只从扩展自有目录加载 Catalog 白名单资产；规范化路径后确认仍在该目录内，拒绝绝对外部路径和目录穿越。
- 前端不直接使用 Node 文件系统；资产根目录按现有 CEP/Host 边界可信传入并校验。
- 构建和发布校验哈希、映射与缺失文件；运行时至少核验路径、文件存在及加载后的结构。运行时哈希能力另行评估，不能声称哈希本身能隔离恶意预设。
- 不在线下载缺失模板，不修改 AE 安装目录，也不替换用户自己的预设文件。
- 未来测试仍通过同一 `dev-extension/`；只有正式交付节点才做发布包。

## 7. 加载生命周期与失败处理

### 7.1 正常执行

1. 既有 Action 取得新鲜 Context，Host 再确认合成、工具参数、语言和所需模板。
2. 在修改工程前尽量完成版本、资产、参数约束等预检。任何失败都先决定安全降级或拒绝。
3. 业务 Action 开启唯一的外层 Undo Group，记录本次创建的对象和必要的原始状态。
4. 创建该工具的新图层/控制器；Loader 保存选层、属性选择及当前时间，暂时只选择目标层，清除会影响应用的属性选择。
5. 对隔离的目标加载审核过的控件模板；不能假设调用某层的 `applyPreset()` 就天然只影响该层。选层隔离实现可参考 [RxLab 的包装逻辑](https://rxlab.guide/dusan/reference/DuAEF_DuSan_api.jsxinc.html)。
6. 重新取得效果和属性，核验 matchName、签名、映射、类型和新增效果数量。只返回已验证的参数访问结果。
7. 业务 Action 初始化上下文相关值并安装表达式，检查 `expressionError`、预期维度和采样结果；不只检查“赋值没抛异常”。
8. Loader 恢复其临时状态；最终选中哪个新对象仍由原有业务 Action 决定。失败则恢复用户原选层，不擅自跳转面板。
9. 关闭 Undo Group，通过现有 `ActionResult` 和五语言反馈返回实际结果；不把未完成对象报告为成功。

Helper 不嵌套管理另一套撤销事务。Undo Group 方便用户撤销，不等于异常发生后自动回滚。

删除本次创建的对象也不能作为“已清除 AE 会话内定义注册状态”的证明。发生定义冲突时停止加载，不尝试覆盖同一 matchName 强制重试；在干净会话中复验是兼容测试的一部分。

### 7.2 降级及清理原则

第一阶段只允许修改本次新建、且归该 Action 所有的对象；已识别实例的幂等复用不得重写其参数。尚未实现迁移前，不把 Loader 当作改造任意已有图层的通用入口。

| 情况 | 处理 |
| --- | --- |
| 模板缺失、版本未验证 | 若该业务有已验证的等价原生控件路径，可提示后降级；否则拒绝 |
| 模板加载后结构不符 | 清理本次新建对象，报告模板错误；不得继续用猜测的索引 |
| 部分控件或表达式创建失败 | 精确清理本次对象；仅在确认恢复干净且有等价方案时重新走降级 |
| 存在同名用户效果/多个不明实例 | 保留原对象，报告冲突；禁止覆盖或取第一个匹配项 |
| 清理或恢复状态失败 | 明确报告失败及可能残留，不继续叠加一次重试，不报告成功 |

原生控件降级不是伪效果的静默替代；应在现有反馈中说明“已使用标准控件创建”。复杂分组功能若无等价方案，不能只创建部分参数冒充完整成功。

清理只使用本次记录的对象身份，不按 `Nya` 名称前缀批量删除。禁止覆盖已有关键帧、表达式、用户效果或依赖层。失败码建议区分资产缺失、宿主不兼容、模板不匹配、实例歧义及绑定失败，映射到现有结果协议，不新建平行反馈系统。

## 8. 五语言策略

面板语言与 AE 效果控件标签不是同一套实时界面；不能认为切换 React 语言就会刷新已经创建的伪效果。

规划规则：

1. 复用现有 `zh-CN / zh-TW / en / ja / ko` 文案来源，不另建语言设置。
2. 新实例采用执行 Action 的语言；已有实例保持创建时语言。切换面板语言不扫描工程、不替换效果、不重接表达式。
3. 原型可先以单一固定语言验证结构；正式五语言目标优先研究独立、不可变的语言模板变体，各自具有不同 matchName。
4. 不使用同一 matchName 在一个 AE 会话中反复注册不同语言定义；语言变体保持相同语义规格，但映射仍按各自实际导出物验证。
5. 同一工程混合语言控件必须能共存。表达式读取的是语义对应的属性和实例，而非“宽度/Width”的字面字符串。
6. 未验证的语言模板不能作为正式能力发布；暂时保留原生路径时沿用其现有行为并明确反馈，不伪称其标签已自动本地化。
7. 参数名称保持简短，单位统一；分组/菜单的长度和中日韩字符显示单独检查。下拉选项的业务枚举值不随翻译顺序变化。

语言变体共存、标签长度和跨 AE 界面语言行为均是可行性与兼容门槛，不是本规划已确认的结果。旧实例换语言若以后确有需求，应作为显式迁移工具另立规格。

## 9. 版本与旧工程保护

### 9.1 发布后不可原地改结构

- 分开记录参数结构版本、模板资产版本和绑定版本；不能仅使用 NYAWORKS 整体版本推断属性布局。
- 已发布 matchName 对应的定义不可原地换成另一套布局。重新排序、增删分组或参数、更改类型/单位/枚举含义，按不兼容变更处理。
- 不兼容变更使用新模板身份和 matchName；已确认有问题的旧成品从后续交付和当前 Catalog 删除，不为了兼容而随包保留。仍有效的旧结构是否需并存，须单独通过旧工程兼容验收决定，不能自动继承“保留”规则。即使只是追加参数，也先视作需验证的新定义，不能假设安全。
- 只改业务算法也要记录绑定版本和行为变化；新实现只作用于新建实例，不能在打开面板时重写旧表达式。
- 同一安装中若匹配到同名但不同结构的定义，拒绝复用，不靠再次注册覆盖。
- 删除错误成品不等于删除 AE 工程中已创建的旧控件；本工具不扫描或自动修复旧工程，遇到旧实例依赖时须单独评估迁移。Git 历史可用于追溯，不等同于在扩展里继续交付错误 `.ffx`。

### 9.2 当前原生控件不迁移

现有圆角矩形、其他形状和摄像机控制器继续使用各自的原生控件与表达式。升级 NYAWORKS 不自动删除它们，不按中文名称批量识别“旧版”，也不在项目打开时全量扫描。

后续若开发显式迁移工具，必须另行覆盖：

- 用户选择范围和迁移预检报告。
- 精确识别旧版生成结构；未知修改、外部依赖不明时拒绝。
- 数值、关键帧时间/插值、表达式、启用状态、层引用和控制关系保留。
- 外部表达式引用旧控件的处理；不能只复制当前帧数值后删旧效果。
- 单次撤销、失败恢复、迁移前后采样比较和新旧版本并存测试。

第一阶段不实现“一键升级全工程”“自动修复所有表达式”或“切换语言重建控件”。

### 9.3 工程可携带性

目标是保存后的工程不依赖 NYAWORKS 面板进程或制作器继续运行；是否仍需要 NYAWORKS 才能新增/升级控制器，与已有工程能否调参、渲染是两件事。

必须在未安装制作器、未修改 XML、未安装 NYAWORKS 的环境测试已生成工程的打开、调参和渲染；不能仅在制作模板的电脑上测试。任何 Missing 提示、字体/素材/真实插件缺失都要分类记录，不能把伪效果分发能力说成工程全部依赖都会自动打包。

## 10. 分阶段推进与验收

以下实现任务全部未开始。本规划不改变核心工具优先、Nya Pie 暂停在技术底座的总路线；是否启动各阶段由后续任务决定。
