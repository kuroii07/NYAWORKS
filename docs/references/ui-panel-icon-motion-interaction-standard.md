# NYAWORKS UI / 面板 / 图标 / 动效 / 交互参考标准

版本：`1.0`
建立日期：`2026-10-05`
适用范围：NYAWORKS 及后续同类创作工具项目

## 1. 文档定位

本标准用于统一 NYAWORKS 后续功能页、AE 面板、首页快捷工具、图标、动效和交互的设计判断。

这里的资源是“参考与评审基线”，不是必须全部安装或照搬的依赖。任何功能仍需先证明真实 AE 场景价值，再决定是否进入产品。

参考优先级：

1. Adobe 官方设计与开发规范；
2. NYAWORKS 当前架构、主题、国际化、Action 和 Host 安全边界；
3. 项目指定的 IconPark 图标来源；
4. 其他第三方项目、素材库和动效网站的场景参考。

## 2. Adobe 官方 UI 与面板参考

### 2.1 Spectrum Web Components（SWC）

来源：[Spectrum Web Components](https://opensource.adobe.com/spectrum-web-components/)

SWC 是 Adobe 官方 Web 组件体系，主要用于参考：

- Adobe 产品的控件层级、状态、间距和交互语义；
- Button、Dialog、Field、Menu、Tabs、Tooltip、Picker 等基础组件；
- 深色专业软件中的可读性、禁用态、焦点态和错误反馈；
- 组件在窄面板、高 DPI 和键盘操作下的行为。

当前 NYAWORKS 仍是 React + Vite + CEP，不因为参考 SWC 就直接迁移到 Web Components 或 UXP。除非单独完成技术评估，否则优先把 SWC 的视觉和交互原则转译到现有组件与 `--nw-*` Design Token 中。

### 2.2 UXP 示例与模板

Adobe UXP 开发文档和示例用于参考：

- 新项目的插件入口、生命周期和权限边界；
- Adobe 宿主环境中的面板组织方式；
- UXP 与 React 包装方案（例如 ruxp）在新项目中的可行性；
- 将 UI、宿主调用和本地能力分层的方式。

UXP 参考不改变 NYAWORKS 当前 CEP 兼容目标。涉及迁移或新建 UXP 项目时，必须单独记录宿主版本、API 覆盖、权限、打包和回退方案。

### 2.3 传统 CEP 参考

以下项目只作为旧版 CEP 工程和脚手架参考：

- `extendscript_react_library`：React、TypeScript 与 ExtendScript 的 CEP 组织方式；
- `Bolt-CEP`：轻量 CEP 启动模板、构建和调试流程。

NYAWORKS 已有 CEP、Bridge、Host 和 Action 架构时，优先扩展现有实现，不因参考模板重新生成一套平行工程。

### 2.4 ScriptUI 参考

以下工具只用于 ExtendScript / ScriptUI 场景：

- `scriptui-battlestyle`：高清、Retina 图标按钮和 ScriptUI 控件处理；
- `TreeUI`：基于对象描述的树状界面组织。

它们不能直接作为 React/CEP 组件依赖。参考时重点提取高 DPI、树结构、按钮命中区、键盘导航和状态反馈。

## 3. 图标标准

### 3.1 指定来源

NYAWORKS 的图标选型优先使用字节跳动 IconPark 官方图标库：

[IconPark 官方图标库](https://iconpark.oceanengine.com/official)

当前新建图层九宫格已使用 IconPark React 组件；灯光层图标因产品要求保持原样。

### 3.2 选型规则

- 不凭空绘制新的 SVG 图标；
- 不随意混用来源、线宽和视觉语言不同的图标库；
- 同一组工具必须使用同一套来源、同一主题（默认优先 `outline`）和一致线宽；
- 图标先按真实功能语义选择，再考虑识别度和视觉平衡；
- 文字、图层、摄像机、空对象、预合成等专业语义优先选择直接表达动作或对象的图标；
- IconPark 中没有合适语义时，保留现有图标或提交单独的图标评审，不用相近但容易误解的图标凑数；
- 纯图标按钮必须有 Tooltip、无障碍名称和键盘焦点反馈；
- 图标不能替代必须显示的文字说明，复杂动作仍使用图标加短文字或菜单。

### 3.3 兼容与维护

- React/CEP 中优先通过统一适配层使用 IconPark，避免组件页面直接散落配置；
- 组件层只保存稳定的图标 ID，不在业务逻辑中保存 SVG 字符串；
- 更换图标时同步检查首页、全局搜索、布局编辑、Tooltip、Action Registry 和截图文档；
- 旧有 Phosphor 图标不因标准建立而一次性全量替换；只在相关功能修改、视觉不一致或用户明确要求时迁移；
- 同一控件组内不得出现 IconPark 与其他来源的明显风格冲突。

## 4. 动效与视觉灵感参考

以下资源用于观察节奏、状态反馈和视觉表达，不直接复制动画或素材：

- `PQ Mo•Bits`：AE / ScriptUI 动效图标和可停靠面板参考；
- `PQ FUI Toys 3`：HUD、科幻和信息层级动效参考；
- [60fps.design](https://60fps.design)：界面动效节奏、转场和微交互灵感；
- [ReactBits](https://reactbits.dev)：React 动效组件和交互实现参考；
- [Uiverse](https://uiverse.io)：控件状态和 CSS 交互灵感。

NYAWORKS 的默认动效规则：

- 动效服务于状态识别、层级变化和操作反馈，不为装饰而持续运动；
- 优先短促、可预测、可取消的 Hover、Pressed、Focus、Loading、Success 和 Error 反馈；
- 不让动效阻塞 AE 操作，不把关键状态只交给颜色或动画表达；
- 遵循现有 `standard / reduced / off` 动效设置；
- 专业面板优先稳定和响应速度，谨慎使用大幅位移、循环背景和高频闪烁；
- 动效组件必须考虑窄面板、高 DPI、低性能机器和减少动效偏好。

## 5. 交互标准

### 5.1 面板与组件

- 优先延续 Adobe 专业软件的紧凑、高识别、高信息密度特征；
- 使用现有主题、语言、密度和公共组件，不为单个功能建立平行状态系统；
- 宽面板与窄面板都要有明确的收缩策略，不通过挤压文字或隐藏关键操作解决布局问题；
- 纯图标入口提供 Tooltip；危险操作、批处理和不可逆行为提供明确确认与结果反馈；
- 空状态、加载状态、宿主未连接、权限失败和执行失败都必须有可理解提示。

### 5.2 键盘与桌面习惯

- 单击选择，双击或 Enter 执行；方向键和小键盘方向键保持一致；
- `Esc` 取消浮层或当前操作；`Ctrl/⌘ + K`、`Ctrl/⌘ + F` 等快捷键必须避免与 AE 冲突；
- 右键菜单保留桌面软件习惯，菜单宽度、命中区和焦点态不能干扰主面板；
- 选中态、Hover 态和键盘焦点态要区分，但不叠加多层刺眼边框；
- 执行前由前端改善 UX，执行时仍由 Host 重新校验上下文。

### 5.3 多入口与架构

可被首页、功能页、搜索、快捷键或 Nya Pie 调用的能力，优先注册为统一 `actionId`：

`UI Entry → Action ID → runAction() → Action Registry → Host Executor → Bridge → AE Host`

参考网站中的一个功能不能直接变成一个新页面或一套新工具系统。必须先填写：

```text
参考行为：
真实 AE 场景：
保留价值：
NYAWORKS 升级：
拒绝冗余：
计划 Action ID / 多入口：
Host 安全与兼容边界：
```

## 6. 第三方参考的使用边界

- 参考功能目标、交互顺序、状态反馈和实现思路，不复制代码、完整界面或素材；
- 使用第三方图标、动画、代码或组件前，必须核对许可证、商用限制、署名要求和维护状态；
- 灵感网站不自动成为运行时依赖；
- 任何新增依赖都必须说明体积、CEP/AE 兼容性、构建影响和移除方案；
- Adobe 官方规范优先于第三方视觉趋势；
- NYAWORKS 仍以真实 AE 工作流、稳定执行、安全撤销、多语言和窄面板可用性为最终验收标准。

## 7. 开发前检查清单

每个新的 UI、面板、图标、动效或交互功能，至少检查：

- [ ] 是否明确真实使用场景和高频问题；
- [ ] 是否查询了对应的 Adobe / IconPark / 参考资源；
- [ ] 是否复用现有 Theme、Language、Density、Tooltip 和 Action 系统；
- [ ] 是否在宽面板、窄面板、中文、英文和高 DPI 下检查；
- [ ] 是否有键盘、焦点、错误、加载和取消状态；
- [ ] 是否考虑减少动效设置和低性能环境；
- [ ] 是否检查许可证、依赖体积和 CEP 兼容性；
- [ ] 是否完成浏览器 / CEP / 真实 AE 分层验收；
- [ ] 是否把新的长期规则补充到本文，而不是散落在临时任务中。
